# Risks in Development Projects
XP aims to address several common risks encountered in software development:

- **Schedule slips**: Projects taking longer than planned.
- **Project canceled**: Projects being terminated before completion.
- **System does not evolve gracefully**: The defect rate increases as the system grows.
- **Defect rate**: The frequency of bugs in the software.
- **Business misunderstood**: The software doesn't meet the actual business needs.
- **Business changes**: The business requirements evolve during the project.
- **False feature rich**: Developing features that aren't actually needed or valuable.
- **Staff turnover**: Team members leaving the project.
# Cost of Change

# Variables
![[Pasted image 20250526173424.png]]

Software development involves managing four key variables:

- **Time** (Schedule) 
- **Resources** (Budget, Labor) 
- **Quality**
- **Scope** (Features, Functionality) 

Traditionally, external forces (customers, managers) might try to set values for three variables, leaving the development team to manage the fourth.

XP takes a specific stance on these variables:

- **Scope**: Actively managed by the Customer; this is the primary control variable.
- **Quality**: Considered non-negotiable and paramount.
- **Budget (Resources)**: Usually fixed.
- **Time**: Usually fixed, often through a number of fixed-length iterations.
- **Success**: Defined as delivering value to the customer.
# Business Value
- **Core Objective**: A fundamental aim in XP is that project **success is defined as delivering value to the customer**. The transition from traditional approaches to agile methods like XP shifts the focus towards delivering this value effectively.
- **Prioritization by Business**: XP empowers the business (often through the On-site Customer) to set priorities for features. This ensures that the development team focuses on delivering the highest business value first.
- **Maximizing Value through Simplicity**: The XP value of Simplicity ("We will do what is needed and asked for, but no more" ) directly supports maximizing the value created for the investment made.
- **Frequent Delivery of Value**: Practices like Small Releases ensure that each release contains the most valuable business requirements, and working software is delivered frequently, allowing the customer to realize value early and continuously.
