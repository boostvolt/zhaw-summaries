Software Craft (often referred to as Software Craftsmanship) is a movement and mindset within software development emphasizing professionalism, technical excellence, continuous learning, and the creation of well-crafted software.
# Manifesto
## A Call for Quality and Professionalism
A strong desire emerged within the developer community to move beyond merely functional software and to combat poor practices. This included a commitment to:    

- Not creating a mess to meet schedules.
- Rejecting the idea of "cleaning up later".
- Not equating speed with "dirty" code.
- Refusing to intentionally do things wrong.   
- Resisting pressure to act unprofessionally.
## Building Upon Agile Values
The Manifesto for Software Craftsmanship (2009) was created to elevate the standards of professional software development. It extends the Agile Manifesto by adding a focus on the quality of work and the broader professional community:

- Not only **working software**, but also **well-crafted software**.
- Not only **responding to change**, but also **steadily adding value**.
- Not only **individuals and interactions**, but also **a community of professionals**.
- Not only **customer collaboration**, but also **productive partnerships**. The core message is that the craftsmanship aspects on the right are indispensable for achieving the agile goals on the left.
## Purpose of the Craft Manifesto
- To establish and give voice to a community valuing these ideals.    
- To increase the visibility of craftsmanship principles.    
- To develop schools of thought around these practices.    
- To offer guidance for new developers aspiring to professionalism.
# Community
## Formats
- **Conferences and Gatherings**: International and local conferences like SoCraTes (Software Craft and Testing) play a significant role, often using an unconference format that encourages active participation.
- **Local Communities & Meetups**: Groups like Software Crafters Zurich and Manila, and networks like Softwerkskammer in the DACH region, organize regular events. These include architectural Katas, Coding Dojos, knowledge exchanges, and moderated discussions. Softwarecrafters.org acts as a hub.
- **Specific Practice Events**: Coding Dojos, Code Retreats, Open Space sessions, Birds of a Feather (BoF), LeanCoffee.org, Hackergarten.net, and Codersonly.org.
## Exchange
- Learning happens primarily _with_ and _from_ each other.
- The community often resembles a "Zunft" or guild, focusing on:
    - Discussing craft topics.
    - Practicing together.
    - Defining standards.
    - Sharing knowledge.
    - Supporting structures like journeyman/craftsman swaps and apprenticeships.
## Guiding Principles
- **Well-Crafted Software**: Prioritizing not just functional software but software that is well-designed, clean, and maintainable.
- **Steadily Adding Value**: Focusing on continuous, valuable contributions rather than just reacting to change.
- **Community of Professionals**: Building and participating in a community that supports learning and growth.
- **Productive Partnerships**: Aiming for collaborative and mutually beneficial relationships with customers/clients.
- **Continuous Improvement & Lifelong Learning**: Recognizing that skills must be constantly honed and updated through practice and learning new things. The rapid growth in the number of developers underscores this need.
- **Clean Code**: An attitude and practice of writing clear, understandable, and high-quality code.
# Practice
- **Dedicated Practice Time**: Professionals should invest personal time (e.g., an additional 20 hours a week beyond employer work) in activities that enhance their career, such as reading, learning new languages/technologies, and dedicated practice exercises. This should be enjoyable and reinforce passion.
- **Specific Practice Formats**:
    - **Code Katas**: Small, focused exercises repeated to build muscle memory and refine technique.
    - **Coding Dojos**: Collaborative sessions for group practice and learning.
    - **Code Retreats**: Intensive, day-long practice events.
    - **Applying Clean Code Principles**: Consciously writing clean code in all development work.
    - **Code Koans**: Exercises to learn a language or paradigm by fixing failing tests.
- **Broadening Experience & Continuous Learning**:
    - Actively learn new programming languages, paradigms, and tools outside of one's primary expertise.
    - Engage with learning resources: read books, articles, blogs.
    - Attend conferences and user groups.
    - Participate in study groups.
- **Mentoring and Apprenticeship**: Teaching others is a powerful way to solidify one's own understanding. Professionals take responsibility for mentoring juniors.
## Coding Dojo
- **Definition**: A collaborative meeting where developers practice software development techniques, methods, languages, frameworks, or tools together. The term "Dojo" signifies a training space, and the goal is to learn with and from one another.
- **Environment**: A safe space without managerial pressure or deadlines, designed to practice skills that are hard to acquire and easy to lose.
- **Focus**: In professional settings, Dojos often focus on exploring new technologies or tackling real-world challenges rather than just basic exercises.
### Formats
- Can involve multiple pairs programming simultaneously.
- A common format is the Randori (or cyclical development) style: one pair codes at a projector (pilot/co-pilot), thinking aloud, while the audience observes and provides feedback. Roles (e.g., one person from the pair) rotate with someone from the audience at short intervals (e.g., 5-10 minutes).
### Principles & Rules
- The session starts by agreeing on the topic, task, approach, and timebox.
- Communication is respectful and at eye level; the learning process is valued over achieving a perfect solution.
- Openness to alternative approaches is encouraged, while still avoiding unnecessary code.
- "Design cannot be discussed without code, code cannot be shown without tests" is a common guiding principle.
- Continuous repetition fosters skill and team cohesion.
## Code Kata
- **Definition**: A small, well-defined programming exercise that developers practice repeatedly to improve specific skills, similar to how a martial artist practices forms (Katas). The focus is on the process of solving and the learning that occurs, not just achieving a correct answer.
- **Types**: Include Function Katas (e.g., FizzBuzz ), Class Katas (e.g., Bowling Game Kata ), Library Katas, Application Katas, and Architecture Katas.
- **Resources**: Numerous online "Katalogs" provide collections of Code Katas.
### Characteristics
- **Repetition**: Designed to be done many times, with small improvements or variations in each attempt.
- **Short Duration**: Often designed to be completed in a short time (e.g., 30 minutes to 1 hour) to allow for regular, even daily, practice.
- **Skill Focus**: Used to train "fingers and brain," sharpen specific skills like using TDD (often a default pattern ), keyboard shortcuts, or particular refactorings.
- **Varied Content**: Some involve specific programming solutions, while others are open-ended, focusing on thinking about broader issues like software architecture
