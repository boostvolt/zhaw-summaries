# Source Code Anatomy
## Declaration vs. Definition
### Declaration ("Versprechen")
**Purpose:** Specifies how a name (function, variable, or type) can be used without allocating memory or implementing functionality.

```
uint32_t square(uint32_t v);   // Function declared (body defined elsewhere)
extern uint32_t counter;       // Variable declared (memory allocated elsewhere)
struct S;                      // Struct type declared (members defined elsewhere)
```
### Definition ("Tatsächlich")
**Purpose:** Implements a function, allocates memory for a variable, or fully defines a struct with its members.

```
uint32_t square(uint32_t v) { ... }  // Function definition with body
uint32_t counter;                    // Variable definition with memory allocation
struct S { int x; int y; };          // Struct type fully defined with members
```

## Linkage
**External linkage**
- Global name is externally available for use in any module
- E.g. a function or a global variable

**Internal linkage**
- Global name is only internally available for use in this module
- E.g. a function or a global variable

**No linkage**
- Any name that is not in the global space
- E.g. a local variable

## Import & Export
**EXPORT**: Declares a symbol for use by other modules
**IMPORT**: Declares a symbol from another module for use in this module

# Linker
## Object Files
Contains all compiled data of a module. ARM tool chain uses ELF for object files.
- ELF = **E**xecutable and **L**inkable **F**ormat
- Includes the above mentioned sections as well as further sections (e.g. string tables, debugging information, etc.)

**Code section**
Code and constant data of the module, based at address 0x0.

**Data section**
All global variables of the module, based at address 0x0.

**Symbol table**
All symbols with their attributes like global/local, reference, etc.

**Relocation table**
Which bytes of the data and code section need to be adjusted (and how) after merging the sections in the linking process.
## Executable File
Contains all linked data of the program. ARM tool chain uses ELF for executable file.
- File extension: AXF = **A**RM e**X**ecutable **F**ile

**Code section**
Code and constant data of the program.

**Data section**
All global variables of the program.

**Symbol table**
All symbols with their attributes like global/local, etc. (level of detail configurable for e.g. debugging)

**Relocation table**
If needed. Adjusts addresses for unresolved symbols or dynamic linking. Happens if the program is loaded before execution by a loader of the OS.
